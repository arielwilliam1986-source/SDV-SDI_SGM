3. COMO SE CORRIGIO (con detalle tecnico)
--------------------------------------------------------------------------------

Se anade una funcion nueva, _formas_conservadoras(fn, alias), que recorre el
cuerpo de la funcion y devuelve la lista de construcciones peligrosas:

  (tipo, linea, fragmento)

  Tipos detectados:
    anotada             ast.AnnAssign cuyo value toca el alias
    encadenada          ast.Assign con len(targets) > 1 y value toca el alias
    desempaquetado      ast.Assign con target Tuple/List y value toca el alias
    namedexpr           ast.NamedExpr cuyo value toca el alias
    atributo/contenedor ast.Assign con target Attribute/Subscript y value toca
                        el alias  (obj.ref = arr  /  d["k"] = arr)
    paso_a_llamada      llamada con un argumento del alias en cualquier posicion
                        (lista.append(arr), registrar(arr), ...)

  "toca el alias" = la expresion referencia alguno de los nombres del conjunto
  de alias de esa variable de bucle, calculado con _alias_de().

Se evalua POR VARIABLE DE BUCLE, con SU conjunto de alias, porque cada
variable puede tener alias distintos.

En _analizar_funcion(), si aparece alguna forma:

    if formas:
        detalle = '; '.join('%s: %s@%d' % (v, f[0][0], f[0][1]) ...)
        out['formas'] = {...}                 # se guarda el detalle
        return dict(out, estado=F_DUDOSO,
                    motivo='formas no seguidas que pueden retener la '
                           'referencia: %s' % detalle)

Se devuelve F_DUDOSO (NO_CONCLUYENTE). Nunca F_OK.

ORDEN DE LAS COMPROBACIONES en _analizar_funcion (importante):
  1. variables de bucle que recorren el contenedor
  2. FORMAS CONSERVADORAS nuevas
  3. rebindings (_reasignaciones_previas, modelo de vidas de la revision 2)
  4. evaluacion de todos los caminos
  5. decision final

Las formas se comprueban ANTES que el modelo de vidas, a proposito: el modelo
de vidas sirve para justificar REASIGNACIONES ya cubiertas, NO para justificar
alias que el detector no ha identificado (punto 3 del encargo de Cris).

4. MODELO DE VIDAS: QUE SE CONSERVA Y QUE NO
--------------------------------------------------------------------------------

Se CONSERVA exactamente igual que en la revision 2:

  - un nombre "vive" desde su definicion hasta su `del`;
  - `x = None` es LIBERACION;
  - reasignar un nombre VIVO es rebinding (dudoso);
  - reasignar un nombre YA BORRADO es una VIDA NUEVA (patron legitimo
    mm = {}; del mm; mm = {}; del mm);
  - los nombres de bucle los define el `for`, asi que toda asignacion posterior
    sobre ellos rebindea.

Se deja CLARO que NO se usa para:
  - justificar alias no identificados;
  - convertir en TRUE un caso donde aparezca una forma conservadora.

Prueba de que el modelo sigue vivo y funcionando: el banco _t_det3.py de la
revision 2 (que contiene M1, M2, M3, D3, V1, V2) sigue 16/16.
