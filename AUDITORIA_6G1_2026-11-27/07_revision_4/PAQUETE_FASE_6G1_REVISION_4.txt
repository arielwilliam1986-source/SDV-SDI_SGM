1. EL CAMBIO DE MODELO (punto 4 del encargo)

1.1 LO QUE HABIA (revision 3)

    _formas_conservadoras(fn, alias) recorria el arbol buscando seis patrones
    concretos: AnnAssign, Assign encadenado, desempaquetado, NamedExpr,
    Attribute/Subscript como destino, y paso a llamada.

    PROBLEMA ESTRUCTURAL: si una construccion no estaba en esa lista, no se
    generaba ninguna marca. El silencio era el valor por defecto. Eso es
    justo lo que el encargo prohibe.

1.2 LO QUE HAY (revision 4)

    Se invierte la carga de la prueba. Para CADA aparicion del alias se examina
    el nodo PADRE y se clasifica:

        _clasificar_contexto(padre, campo, alias) -> (tipo, descripcion)

    Solo devuelve (None, None) -- es decir, "inocuo" -- en estos casos:

        atributo LEIDO       arr.attr        (padre Attribute, campo value)
        subindice LEIDO      arr[i]          (padre Subscript, campo value)
        llamada PURA         len(arr), id(arr), isinstance(arr, T), ...

    Todo lo demas devuelve un tipo con nombre propio y se acumula. Entre otros:

        anotada              b: T = arr
        encadenada           b = c = arr
        desempaquetado       b, = (arr,)
        atributo/contenedor  obj.ref = arr  /  d["k"] = arr
        asignacion           b = arr        (se exime: la modela el detector)
        augassign            arr += 1
        retorno              return arr
        yield / yield_from   yield arr / yield from arr
        namedexpr            (b := arr)
        paso_a_llamada       lista.append(arr), registrar(arr)
        llamada_callee       arr()  (el alias es la funcion)
        contenedor_literal   [arr] / (arr,) / {arr}
        dict_literal         {"k": arr}
        comprehension        [x for x in arr], (arr for _ in z), ...
        expresion_derivada   arr is not None, arr + 1, f"{arr}"
        global_nonlocal      global arr / nonlocal arr
        with_as_alias        with ... as arr
        contexto_desconocido CUALQUIER OTRO NODO  <-- fallo cerrado

    La ultima linea es la clave del punto 4: si aparece un padre que no se ha
    clasificado, NO se ignora; se marca como contexto_desconocido y el
    resultado pasa a NO_CONCLUYENTE. Una construccion nueva de Python no puede
    colarse en silencio.

2. LOS DOS HALLAZGOS GRAVES: `with` Y `match`
--------------------------------------------------------------------------------

2.1 EL DEFECTO

    _caminos(cuerpo, ...) recorre las sentencias de un bloque y trata:

        Delete        -> cierra un camino
        If / Try      -> explota sus ramas
        For / While   -> explota o aplana
        TODO LO DEMAS -> _simple(s, cont, alias)

    _simple() solo reconoce Delete, Assign y llamadas. Para un ast.With o un
    ast.Match devuelve LISTA VACIA. Como esas sentencias tampoco estaban en la
    cadena de isinstance, sus hijos no se visitaban nunca.

    Consecuencia: un alias creado dentro de un `with` o de un `case` era
    invisible. El camino quedaba con los eventos de fuera, parecia limpio, y el
    veredicto era CONCLUYENTE_TRUE.

2.2 REPRODUCCION (ejecutada, propuesta de la revision 3)

    caso                                  estado rev.3   eventos del camino
    ------------------------------------  --------------  ---------------------
    with: b = arr dentro del cuerpo       C_TRUE          ruido, muta, lib, del
    match: b = arr en un case             C_TRUE          ruido, muta, lib, del

    Ninguno de los dos caminos contiene un evento de fuga: el alias
    simplemente no existia para el detector.

2.3 CORRECCION

    Se anade el recorrido de ambas construcciones en los DOS sitios donde se
    procesan sentencias, porque cada uno tiene su propio bucle:

      a) _flat()   (para bloques que no contienen el del)
      b) _caminos() (para bloques que si lo contienen)

    WITH:
        - cada item se evalua como expresion (el __enter__ puede lanzar);
        - `with ... as X` anade un evento de mutacion (liga X);
        - el cuerpo se aplana o se explota, segun contenga el del.

    MATCH:
        - el sujeto se evalua;
        - cada `case` es una RAMA, igual que un if/else;
        - si un case contiene el del, se explota, PERO marcado con un evento
          condicional: el del solo ocurre si ese case coincide;
        - si un case no borra y la referencia pudo quedar viva, es un camino
          valido sin del -> incompleto -> no concluyente.

2.4 VERIFICACION

    caso                                  antes     ahora
    ------------------------------------  --------  -------------------
    with: b = arr dentro del cuerpo       C_TRUE    C_FALSE
    match: b = arr en un case             C_TRUE    C_FALSE
    with ... as arr                       C_TRUE    NO_CONCLUYENTE
    match con del dentro de un case       C_TRUE    NO_CONCLUYENTE
    with abrir() as q: arr = None         C_TRUE    C_TRUE  (control OK)

3. `global` Y `nonlocal`: INVISIBLES POR CONSTRUCCION
--------------------------------------------------------------------------------

    ast.Global y ast.Nonlocal no cuelgan ningun ast.Name de sus hijos: guardan
    los nombres en el campo .names como CADENAS de texto.

        ast.Global(names=['arr'])

    Por tanto, cualquier estrategia basada en "recorrer los nodos Name y mirar
    su padre" es CIEGA a estas dos construcciones, por muy completa que sea la
    lista de patrones. Es un caso donde ampliar la lista no habria servido de
    nada jamas: habia que tratarlas aparte.

    Correccion:

        for nodo in ast.walk(fn):
            if isinstance(nodo, (ast.Global, ast.Nonlocal)):
                for nom in nodo.names:
                    if nom in alias:
                        fuera.append(('global_nonlocal', nodo.lineno, ...))

    Verificacion: `global arr` y `nonlocal arr` pasan de CONCLUYENTE_TRUE a
    NO_CONCLUYENTE.

4. OTROS DOS AJUSTES QUE EL ENDURECIMIENTO HIZO NECESARIOS
--------------------------------------------------------------------------------

4.1 LLAMADAS PURAS

    Al tratar todo paso a llamada como no soportado, `len(arr)`, `id(arr)` o
    `isinstance(arr, T)` tumbaban controles legitimos (P05 daba
    NO_CONCLUYENTE). Estas funciones LEEN el objeto y no guardan su
    referencia. Se anade una lista CERRADA y conservadora:

        len, id, hash, repr, str, type, bool, int, float, isinstance, callable,
        iter, abs, hex, oct, bin, format, ascii, vars, dir, getattr, hasattr,
        sizeof

    La lista se aplica en los dos sitios donde antes se marcaba paso a
    llamada: _formas_conservadoras (por contexto) y _pasa_a_funcion (que
    genera el evento _PASA). Ambas deben coincidir o el evento seguiria
    apareciendo.

    LIMITACION: es una lista cerrada. Una funcion pura que no este en ella se
    tratara como no soportada -> NO_CONCLUYENTE. El error va en la direccion
    segura (dudar), nunca en la de dar TRUE.

4.2 `with ... as <alias>`

    `with abrir() as arr:` re-liga el propio nombre del alias. El detector
    creeria que `arr` sigue siendo el memmap cuando ya no lo es, y ademas el
    memmap original puede seguir vivo en otro sitio. Se detecta y se marca:

        with_as_alias   'with ... as arr'

10. LIMITACIONES QUE SIGUEN ABIERTAS
--------------------------------------------------------------------------------

  L-1  TOCTOU T-1..T-4 documentadas, sin resolver.
  L-2  PDA-1 (escrituras ancladas por descriptor) NO implementado.
  L-3  Validacion de enlaces no atomica. NO se declara aislamiento completo.
  L-4  El detector F es ESTATICO. validacion_dinamica sigue PENDIENTE.
  L-5  El fallo cerrado cubre la RELACION padre-hijo directa. Un alias puede
       viajar por un camino que no produzca un contexto desconocido pero que
       el modelo de _juzgar no sepa seguir (por ejemplo, un alias liberado
       bajo una guarda distinta). Eso lo cubre _juzgar con 'dudoso', no la
       enumeracion de contextos.
  L-6  _LLAMADAS_PURAS es una lista cerrada; una funcion pura no listada se
       tratara como no soportada. El error va hacia dudar, nunca hacia TRUE.
  L-7  No se modela el flujo entre funciones (una funcion llamada puede
       guardar la referencia en un global). Se marca como paso_a_llamada ->
       NO_CONCLUYENTE, que es lo conservador.
  L-8  `with`/`match` se recorren, pero NO se modela la semantica de que un
       `with` puede suprimir excepciones ni la de los patrones de `match`
       (guardas, or-patterns). Se aplana el cuerpo; si hay del condicional
       dentro de un case, se marca condicional -> dudoso.
  L-9  N19/N22 dan CONCLUYENTE_FALSE y es correcto: el alias se crea dentro
       del bloque y sobrevive; la fuga es demostrable.
